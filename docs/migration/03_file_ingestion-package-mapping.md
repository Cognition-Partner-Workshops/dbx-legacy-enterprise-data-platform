# 03_file_ingestion -> Databricks: package mapping

Session 03 of the SSIS -> Databricks migration. Source project `ssis/03_file_ingestion/`
(`WWI_Ingest_Files`, generated by `generate_file_ingestion.py`); target bundle
`databricks/03_file_ingestion/` (bundle and job `wwi_03_file_ingestion`).

All seven `ING_FILE_*` packages are migrated. Each becomes one Python source notebook that
runs the shared `wwi_file_ingestion` runner (in `databricks/03_file_ingestion/src/`) over a
`FeedSpec` derived from the flat-file connection manager of the package and
`config/landing-zone.yaml`.

### Trigger

`resources/wwi_03_file_ingestion.yml` carries a `file_arrival` trigger on
`/Volumes/${catalog}/bronze/inbound/` with `min_time_between_triggers_seconds: 900` (the legacy
15-minute cadence as the upper bound) and `wait_after_last_change_seconds: 60`. It is deployed
`PAUSED` by default (`var.file_arrival_pause_status`) so that session 00's master job stays the
scheduler of record; flip the variable to `UNPAUSED` per target to let the volume drive the job.

the manifest; re-running the same `BatchId` re-processes only files not yet finalised in
`etl.file_ingestion_log`, and a re-delivered file of the same name+size is routed as Duplicate.

## 5. Data-flow logic per package

All data flows start `Flat File Source -> Split Record Types (Conditional Split) -> Parse ... (Derived
Column) -> Validate ... (Conditional Split) -> Count ... (Row Count) -> raw destination`, with the
error outputs of the source and of the derived column landing in `err.RejectedFileRow`. Precedence
is preserved exactly: a row that fails a cast in the Derived Column leaves as `CONVERSION` **before**
the Validate split can classify it (e.g. a carrier timestamp shorter than 19 characters or with a
bare `Z` suffix, a supplier `EffectiveFrom` that is not `yyyyMMdd`).

| Package | Record types | Derived columns kept | Validate rule (reject code) | Extra control tasks |
|---|---|---|---|---|
| PartnerSales_NA | `H`ader / `D`etail / `T`railer; anything else -> `UNKNOWN_RECORD_TYPE` | `TransactionDate` (MM/dd/yyyy), `Quantity`, `UnitPrice`, `TaxAmount = StateTax + CountyTax`, `LineTotal`, `GrossAmount` | `PartnerCode`, `TransactionNumber` non-empty and `Quantity > 0` (`MALFORMED`) | footer `T` count read (`Read Footer Record Count`) |
| PartnerSales_EU | `1` detail / `9` footer | decimal-comma -> `GrossAmount`, `VatRate`; `Back Out VAT`: `NetAmount = Gross / (1 + VatRate/100)`, `VatAmount`; `MarketableFlag` from `ConsentFlag` | `VatRegistrationNumber` >= 8 chars and `ReceiptNumber` non-empty (`VAT_MISSING`) | footer `9` amount read |
| PartnerSales_APAC | `#HDR` / detail / `#TOTAL` (no header row, tab) | `TransactionDate` (yyyyMMdd), `GrossAmount`, `GstAmount`, `TaxTreatmentCode = GST`, `PostalCode` left-padded to 6 (`PostalDistrict`) | `SlipNumber`, `ItemCode` non-empty and `Quantity > 0` (`MALFORMED`) | footer `#TOTAL` amount read |
| CarrierScan | single record type | `ScanTimestampUtc = SUBSTRING(ts,1,19)`, `ScanOffsetMinutes = hh*60+mm` of the offset digits (sign ignored, as the package did), `ExceptionFlag`, `DeliveredFlag` | `TrackingNumber`, `ScanStatusCode` non-empty and `LEN(ts) >= 19` (`SCAN_MALFORMED`) | `Read Sidecar Control Count` (`etl.file_control_total`), `Count Duplicate Scans` (duplicates counted, not rejected) |
| SupplierCatalog | `HDR` / `DTL` / `TRL` | `EffectiveFromDate`, `EffectiveToDate` (8-char guard), `ListPrice`, `NetPrice`, `PackSize`, `LeadTimeDays`, `HazardousFlag` | `SupplierItemCode` non-empty, `NetPrice >= 0`, `ListPrice >= NetPrice`, `LEN(EffectiveFrom) == 8` (`CATALOG_BAD`) | `Compute Price Checksum` vs `TRL` checksum — the only control total that poisons a file in the legacy packages |
| FxOverride | `H` / `D` / `T` | `RateDate`, `OverrideRate`, `RatePairCode = From+To`, `FourEyesFlag = ApprovedBy non-empty and != RequestedBy`; `Lookup Published Rate` (left join on `RatePairCode`, `RateDate` against SPOT rates), `DeviationBasisPoints` | precedence: no published rate -> `FX_UNKNOWN_PAIR`; else `FourEyesFlag == Y and ApprovalTicketNumber non-empty and DeviationBasisPoints <= 500` else `FX_TOLERANCE` | `Count Refused Overrides` |
| QuarantineMalformed | raw lines of every `quarantine_rejects_*.dat` | `Classify Quarantined Row`: `EMPTY_LINE` / `QUARANTINED`; `ReplayEligibleFlag = Y` when non-empty and no NUL byte | `Split Replayable Rows` -> `err RejectedFileRow Replayable` / `Unreadable` | `Count Replay Eligible Rows`: file `Swept` (archived) when > 0, else `Unreadable` (poison) |

## 6. Control totals, archive, quarantine, duplicates

* **Control totals.** `Reconcile Control Totals` was generated with a clause per package:
  NA `@Landed = ? OR ? = 0` bound to `FooterRowCount`, which is read from
  `err.RejectedFileRow ... RejectReasonCode = 'FOOTER'` — a destination no data flow writes, so it is
  always 0 and the clause is always true; EU `ABS(SUM(GrossAmount)) >= 0`; APAC, Carrier, Supplier
  and FX `@Landed >= 0`. Only SupplierCatalog adds `PriceChecksum == FooterChecksum` on the
  archive/poison edges. `ControlTotalMode` (job parameter, default `legacy`) reproduces exactly that;
  `strict` gates archive on the totals the footers actually carry (NA `T` count, EU `9` amount,
  APAC `#TOTAL` amount, carrier sidecar count, supplier `TRL` count + checksum). Every legacy-mode
  mismatch is still surfaced as a warning in the run summary and the file log.
* **Archive.** Processed files -> `archive/<feed>/<yyyy>/<MM>/`; a `.rej` sidecar with
  `SourceRowNumber|RejectReasonCode|RawRowText` is written to `quarantine/<feed>/<yyyyMMdd>/` for
  every file that had reject rows, whether it was archived or poisoned (the legacy `RejectFilePath`).
* **Poison.** Files failing the control-total gate (or unreadable in the sweep) ->
  `quarantine/poison/`, status `Quarantined` / `Unreadable`, rows already landed stay (as in the
  package, which had no rollback).
* **Duplicates.** `control_totals.isDuplicateFile`: same `FileName` and `FileSizeBytes` already
  `Processed`/`Swept` in `etl.file_ingestion_log` -> file moved to `quarantine/<feed>/duplicate/`,
  status `Duplicate`, nothing loaded, warning logged. Same name / different size is a re-send and
  is loaded (the legacy loop would have reloaded it).
* **Malformed rows.** Every reject row (`COLUMN_COUNT`, `CONVERSION`, `UNKNOWN_RECORD_TYPE`,
  package rule) is inserted into `silver.err_rejected_file_row` with the raw row in `RawRowText` /
  `_rescued_data`, then handed to `control.logRejectedRecordSet` (`etl.rejected_record`).
  `ING_FILE_QuarantineMalformed` sweeps `quarantine_rejects_*.dat` files directly under the quarantine
  volume (the enumerators ran with `Recurse=0`, so the `<feed>/`, `duplicate/` and `poison/` sub-folders
  are never re-swept) and re-registers each line with `OriginFeedCode` / `ReplayEligibleFlag`.

## 9. Generator docstring vs emitted configuration

`generate_file_ingestion.py` describes `ING_FILE_PartnerSales_EU` as *semicolon-delimited* and
`ING_FILE_PartnerSales_APAC` as *Shift-JIS / code page 932*. The emitted `.dtsx` connection
managers and `config/landing-zone.yaml` (the artefacts the estate actually ran with) say EU is
comma-delimited UTF-8 and APAC is tab-delimited ISO-8859-1. The notebooks follow the `.dtsx` /
YAML values; `tests/test_feeds_config.py` pins the feed specs to `config/landing-zone.yaml`.
If the docstrings reflect a newer partner contract this is a one-line `FeedSpec` change.

Reconciliation: `validation/Reconcile_File_Ingestion.py` counts rows per `BatchId` and computes
`sum(xxhash64(concat_ws(business columns)))` for the four bronze tables and the reject table,
compares them with a baseline supplied as a Delta table (`BaselineTable`) or JSON (`BaselineJson`,
`[{"ObjectName":..., "BatchId":..., "RowCount":..., "RowHash":...}]`), logs each comparison through
`control.logRowCount` and fails the task on any mismatch.
