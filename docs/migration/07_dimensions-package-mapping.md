# 07_dimensions — SSIS → Databricks package mapping

Session 07 migrates the `WWI_Dimensions` SSIS project (`ssis/07_dimensions/`, generated by
`build_dimension_packages.py`) and the `Integration.usp_MigrateStaged*Data` / `usp_Load*Dimension`
procedures to the bundle `databricks/07_dimensions/` (`wwi_07_dimensions`). 15 packages → 15 notebooks →
15 tasks in one job.

`STG_* → DIM_*` (other bundles) and `DIM_Rekey_LateArriving → AGG_*` edges, so the intra-project edges are
derived from the lookups each data flow performs (Customer Category → Customer loads → Customer Segment

## 3. Surrogate keys (decision)

**Deterministic key registry, not `GENERATED ALWAYS AS IDENTITY`.** `silver.int_dimension_key_registry`
mirrors `Integration.DimensionKeyRegistry` + the `Integration.seq_<Dimension>Key` sequences: one row per
dimension with `NextKey`, reserved band `-9..0` and real members from `1`. `keys.allocateKeyRange` reserves a
contiguous block per load (as `usp_AllocateDimensionKeyRange` did) and `keys.assignSurrogateKeys` hands the
keys out in business-key order, so a rerun of the same input yields the same keys. Reasons: identity columns
cannot host the negative reserved members, cannot be rewound for a replayed batch, and would break the
"key range per package execution" audit that the legacy lineage relies on. Reserved members (`-1 Unknown`,
`-2 Not Applicable`, `-3 Invalid`, `-4 Inferred Pending`, `-9 Error`) are seeded by `unknown.ensureUnknownMembers`
(`usp_EnsureUnknownMembers`); `0 Not Yet Assigned` is only used inside work tables.

## 4. SSIS component → Spark construct

| SSIS component (generator) | Spark implementation |
|---|---|
| `Execute SQL Task: usp_LogPackageStart / usp_LogPackageEnd / usp_LogError` | `control.packageRun(...)` context manager (`run.rowsRead/rowsInserted/rowsUpdated/rowsRejected`) |
| `Execute SQL Task: usp_EnsureUnknownMembers`, `usp_AllocateDimensionKeyRange` | `runtime.prepareDimension` → `tables.ensureDimensionTable`, `keys.ensureKeyRegistry`, `unknown.ensureUnknownMembers`; `keys.allocateKeyRange` inside `scd.applyScd` |
| OLE DB Source `SELECT … FROM stg.X WHERE BatchId = ?` | `runtime.filterBatch(spark.table(naming.table(catalog, "silver", "stg_x")), batchId, reloadFullHistory)` |
| Conditional Split (DQ status / rule rejects) | `runtime.splitRejects`, `regional.condition*Customers` (rule tuples → `when` chain) |
| Derived Column (bands, codes, defaults, standardisation) | `loaders.transform*` / `regional.py` column expressions |
| Lookup (full cache, ignore failure → -1) | `runtime.lookupSurrogateKey` against `scd.currentMembers` (NULL key → -2, unmatched → -1) |
| Lookup error output → `usp_QueueLateArrivingMember` | `runtime.queueLateArrivingMembers` (MERGE into the queue, bumps `OccurrenceCount`) |
| Row Count transforms → `usp_LogRowCount` | `control.logRowCount(...)` per target object |
| Error output → `err.CustomerReject` / `usp_LogReject` | `control.logRejectedRecordSet(...)` |
| OLE DB Command / `usp_MigrateStaged*Data` (attribute compare, expire, insert) | `scd.applyScd` → `classifyChanges` (NEW / INFERRED / TYPE2 / TYPE1 / UNCHANGED via `xxhash64` row hashes), `MERGE` close-out, key-ordered append; `scd.applyType1Overwrite`; `scd.expireCurrentRows` |
| Sort + Aggregate (dedupe latest staged row) | `scd.deduplicateSource` (window by business key, `changeTimestampColumn` desc, deterministic tie-break) |
| Script Task (manager repair / hierarchy) | `employee.repairManagerKeys`, `employee.refreshHierarchy` (iterative level walk, cap 12) |
| Package parameter `PopulationChangeThresholdPercent` | `control.getConfiguration("Dimension.City.PopulationChangeThresholdPercent")` with default `5.0` |
| `DIM_Rekey_LateArriving` Foreach / SQL tasks | `rekey.runRekey`: classify (`RETRY` / `ESCALATE` / `MANUAL` with NA=3, EU=7, APAC=21, default 5 retries and max queue age), resolve, stub inferred members, `MERGE` fact key repoint, close / retry / abandon (`HOLD_EXPIRED`) |

`dbx_etl_common` is attached as a wheel library on every task (`../../common/dbx_etl_common/dist/*.whl`,
session 00's build output). The `wwi_dimensions` helpers are imported from the bundle's own `src/` via `sys.path`.

## 6. Reconciliation

`validation/reconcile_dimensions.py`: per dimension row count / current count / reserved count / batch rows and
an order-independent `sum(xxhash64(concat_ws(sorted columns)))` content hash; SCD2 chain integrity and
overlapping-window checks (03 §1–2), facts on the unknown member and orphan keys per `FACT_REKEY_TARGETS`
(03 §3–4), open late-arriving queue depth (03 §5 analogue), and the customer-side regional divergence checks
(04 §1–3: each region carries only its own tax construct, uniform retention years, no missing credit currency,
no EU reverse charge without VAT registration). Baseline comes from `etl.reconciliation_baseline` or the
`BaselineJson` widget; everything is logged with `control.logRowCount` and mismatches raise.

## 7. Not migrated / needs decision

| Item | Status / reason |
|---|---|
| `Dimension.Date` / `Dimension.Currency` / `Dimension.[Fiscal Calendar]` | not in `ssis/07_dimensions` (reference refresh, session 06) — 03 §7 date coverage is therefore not in this reconciliation |
| `Fact.[Fact Load Hold]`, `Dimension.[Customer Buying Group Bridge]` (03 §5–6) | fact-side objects owned by the fact sessions; the dimension-side late-arriving queue depth is reported instead |
| Regional sale-level checks (04 §1, §4–7) | operate on `Fact.Sale` / `Aggregate.*`; only the customer-dimension projections are ported here |
| `err.CustomerReject`, `err.RejectedLookupFailure` physical tables | rejects go to `etl.rejected_record` through `control.logRejectedRecordSet`; create dedicated `silver.err_*` tables only if a downstream consumer still reads them |
| Exact band edges (credit limit, quota, price, cost, segment tier) and code vocabularies (`JobGradeCode`, `HandlingCode`, `GoverningLawRegion`, `TaxTreatmentCode` defaults) | the generator emits the column names but the SQL Server reference values were not in the repo; edges live as constants in `loaders.py` — confirm against production `Integration` procs |
| `stg.CustomerAddress`, `stg.Product`, `stg.CustomerSegmentAssignment` | joined when present (`tables.tableExists`) so the bundle also runs before the staging sessions publish them |
| Surrogate-key strategy | deterministic registry (see §3) — confirm identity columns are *not* wanted |
| Legacy `Dimension.Customer` `[Valid From]/[Valid To]` vs `EffectiveFrom/EffectiveTo` | both pairs are kept and written identically; drop one after downstream views are migrated |
| Fact rekey when a fact table does not exist yet | skipped with a `Warning` in `etl.error_log`; rows stay queued and are rekeyed by the next run |
